# Security Policy

## Reporting

Do not disclose security vulnerabilities in public issues.

For private repositories, use the repository's private security reporting mechanism when available.

Never commit API keys, passwords, access tokens, private credentials, production secrets, or sensitive personal data.

## Development Rules

- Keep repositories private by default unless intentionally published.
- Use least-privilege GitHub Actions permissions.
- Review third-party GitHub Actions before use.
- Keep dependencies reasonably current.
- Use .env.example for documented configuration without real secrets.

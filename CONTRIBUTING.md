# Contributing

qu4n-ai currently follows a solo, private-first workflow. These conventions are designed to keep future collaboration straightforward.

## Workflow

1. Create a short-lived branch from main.
2. Make one focused change.
3. Run relevant tests and checks locally.
4. Open a pull request when review or CI is useful.
5. Merge only when checks pass and the change is documented appropriately.

## Branch Names

Use prefixes such as feat/, fix/, research/, refactor/, docs/, and chore/.

## Commit Messages

Prefer concise imperative messages such as `feat: add experiment runner` or `research: evaluate baseline model`.

## Documentation

Important architectural, research, security, and workflow decisions should be documented in the relevant repository or in qu4n-docs.
